# Сравнительный анализ AI Coding Agents: DeepSeek vs OpenCode

> Сравнение результатов двух прогонов на проекте **Investing Demo** (Python/Django) по заданиям из `HOMEWORK.md`.
>
> - Ветка `deepseek-results` — результаты агента **DeepSeek** (папка `agent-deepseek/`)
> - Ветка `opencode-results` — результаты агента **OpenCode** (папка `agent-opencode/`)
>
> Оба агента выполнили задания №1–4, для задания №4 оба выбрали направление «Виртуальный инвестиционный портфель».

## 2. Конкретные примеры

### 2.1 Где DeepSeek справился лучше

**Анализ и требования.** DeepSeek не только описал архитектуру, но и обнаружил скрытые дефекты, влияющие на пользователя. Например, в `agent-deepseek/REQUIREMENTS.md` (DEF-10) зафиксировано, что страницы входа и регистрации рендерятся **без полей ввода**, потому что в `user/views.py` в шаблон передавался класс формы вместо экземпляра — и это дефект был подтверждён и исправлен (`agent-deepseek/user/views.py`). OpenCode этот дефект вообще не нашёл.

**Точность цен (DEF-23).** DeepSeek заметил, что из `Quotation` Tinkoff API берётся только `units`, а `nano` отбрасывается — цена `100.55` сохранялась как `100`. Исправление вынесено в `agent-deepseek/dashboard/services/market_data.py` (`quotation_to_float`: `units + nano / 1e9`) и покрыто **отдельными регрессионными тестами** (`QuotationPrecisionTests` в `agent-deepseek/dashboard/tests_portfolio.py`). У OpenCode этой проблемы в отчётах нет.

**Зависимости.** DeepSeek проверил доступность пакетов через PyPI/GitHub API и установил, что `tinkoff` и `tinkoff-investments` возвращают 404 — SDK удалён из PyPI. Решение: опциональный `agent-deepseek/requirements-tinkoff.txt` + ленивые импорты SDK в `agent-deepseek/dashboard/services/market_data.py`, `graph.py`, `management/commands/add_shares.py` — приложение запускается и проходит тесты без SDK. OpenCode оставил недоступный пакет в `agent-opencode/requirements.txt` (`tinkoff-investments==0.2.0b62`), а совместимость обеспечил **самодельными заглушками** (`tinkoff/__init__.py`, `tinkoff/invest/*` в ветке `opencode-results`) — это маскирует проблему, а не решает её: при попытке реальной установки зависимостей `pip` упадёт.

**Чистота зависимостей.** DeepSeek вынес dev-инструменты в `requirements-dev.txt` и оставил в runtime только прямые зависимости (9 пакетов). В `agent-opencode/requirements.txt` по-прежнему 40+ пакетов, включая black, isort, tomli и весь транзитивный граф.

**Тестовое покрытие новой функциональности.** DeepSeek: 19 тестов в `agent-deepseek/dashboard/tests_portfolio.py`, включая граничные случаи (продажа без позиции, продажа больше остатка с проверкой неизменности состояния, полная продажа, позиции без цены, средневзвешенная цена 100/200 → 150). OpenCode: 5 тестов в `agent-opencode/dashboard/tests_portfolio.py` — основные сценарии есть, но проверок изоляции пользователей, аутентификации и точности расчётов нет.

**Честная деградация.** В `agent-deepseek/dashboard/views.py` карточка акции при недоступном Tinkoff API отдаёт 200 с сообщением «График временно недоступен» вместо 500 (DEF-18), а несуществующий `pk` даёт 404 вместо 500 (DEF-17) — оба случая покрыты регрессионными тестами.

### 2.2 Где OpenCode справился лучше

**Меньше объём при приемлемом качестве ядра.** Реализация buy/sell в `agent-opencode/dashboard/api/v1/portfolio_views.py` компактна, при этом содержит корректную логику: `transaction.atomic` + `select_for_update` с развёрнутым комментарием о конкурентных продажах, пересчёт средней цены при покупке, расчёт `realized_pnl` при продаже, удаление позиции при полной продаже, fallback на рыночную цену `Share.last_price`.

**Работа с дробными числами.** OpenCode квантует значения через `_quantize()` и валидирует цену (`price must be positive`), обрабатывает `InvalidOperation` — базовая аккуратность к Decimal присутствует.

### 2.3 Слабые стороны каждого

| Агент | Слабые стороны |
|---|---|
| DeepSeek | Нет HTML-интерфейса портфеля (только REST API + админка — решение обосновано в `agent-deepseek/FEATURE_REPORT.md`, раздел 1); ряд дефектов осознанно оставлен без исправления (DEF-19 `uid` в API, DEF-32 regex-поиск на PostgreSQL) — хотя они честно задокументированы в разделе 7 `agent-deepseek/MODERNIZATION.md` |
| OpenCode | Незакрытый падающий тест; недоустанавливаемый `requirements.txt`; самодельные заглушки Tinkoff SDK в репозитории; DEF-10 (формы входа/регистрации без полей) не обнаружен и не исправлен; тестовый прогон неполный — запускались отдельные тесты, а полный прогон показывает отказ |

## 3. Вывод: для каких задач какой агент предпочтительнее

**DeepSeek** показал себя значительно сильнее в задачах, требующих глубины и дисциплины:

1. **Аудит и восстановление требований legacy-кода** — 56 требований + систематизированный каталог из 42 дефектов с критичностью против 10 требований и разрозненного списка замечаний у OpenCode.
2. **Модернизация с проверкой фактов** — проверка доступности пакетов в PyPI, корректная стратегия с недоступным SDK, разделение prod/dev-зависимостей, переход на актуальный Django LTS.
3. **Разработка функциональности с высокими требованиями к надёжности** — 19 тестов против 5, покрытые граничные случаи, регрессионные тесты, матрица «требование → тест».

Подходит, когда важны полнота, доказуемость результата (тесты, ссылки на код) и работа с чужим/старым кодом. Плата за это — большие объёмы артефактов и более длительные итерации.

**OpenCode** показал себя быстрее и экономнее:

1. **Быстрое прототипирование новой функциональности** — ядро портфеля (модели + API с транзакциями и блокировками) реализовано корректно при заметно меньшем объёме работы.
2. **Задачи, где достаточно «минимально работающего» результата** — запуск на SQLite, базовая реализация требований.

Подходит для быстрых итераций, MVP и задач с ясным и небольшим объёмом. Однако требует обязательной верификации человеком: агент принимает «обходные» решения (заглушки SDK, оставленный недоступный пакет в зависимостях, списание падающего теста на окружение), которые в `MODERNIZATION.md` и `FEATURE_REPORT.md` подаются как решённые, но при проверке оказываются неполными.

**Итог:** по совокупности заданий №1–4 DeepSeek демонстрирует более высокое качество и надёжность результата (все 33 теста проходят против 14 из 15; полное устранение проблем зависимостей против маскировки заглушками; глубина анализа несопоставима). OpenCode может использоваться как инструмент быстрой разработки, но его результаты требуют более тщательной ревью-проверки.
